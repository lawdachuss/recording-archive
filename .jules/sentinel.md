## 2026-11-01 - IPv6 SSRF Validation Bit-Shift and IPv4-Mapped Normalization Flaw

**Vulnerability:** The SSRF filter in `artifacts/api-server/src/routes/media-proxy.ts` failed to detect and block private IPv6 addresses (Unique Local Addresses `fc00::/7`, link-local `fe80::/10`, multicast `ff00::/8`, and documentation `2001:db8::/32`) as well as IPv4-mapped IPv6 addresses (`::ffff:127.0.0.1`, `::ffff:169.254.169.254`). Attackers could bypass SSRF protections by supplying IPv4-mapped addresses or IPv6 private ranges to reach internal services or cloud instance metadata.
**Learning:** Bit-shift offsets for 128-bit IPv6 CIDR prefix checks were shifted by 96 bits instead of 112 bits for the most significant 16-bit group, resulting in prefix values shifted right by 16 bits. Additionally, converting dotted-decimal IPv4 tails in IPv4-mapped addresses into an 8-character hex string without inserting a colon created an unaligned 32-bit segment that corrupted the BigInt representation.
**Prevention:** In BigInt IPv6 math, calculate group shifts as `(7 - groupIndex) * 16n`, format converted IPv4 tails into two 16-bit segments (`${hex.slice(0, 4)}:${hex.slice(4)}`), and maintain unit test coverage verifying both boundaries and canonical private/reserved IPv6 ranges.
